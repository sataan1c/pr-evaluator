# Участник 4: валидация и множитель

Твоя задача: посчитать множитель для каждого разработчика и доказать, что баллам модели можно верить. На выходе три вещи: `metrics.json` для дашборда, `risk_chart.png` для слайда и три числа из `validation.md`.

## Старт за пять минут

```
pip install matplotlib
python p4.py --dir sample
```

В `sample/` лежит выдуманный репозиторий с баллами от заглушки. Команда проходит все шесть шагов и кладёт результаты туда же. Открой `sample/validation.md` и `sample/risk_chart.png`: так будут выглядеть твои настоящие результаты. Цифры оттуда на слайд не идут, на графике об этом стоит пометка.

## Порядок работы

1. **Пока данных нет.** Запусти `python p4.py --dir sample` и разберись в результатах.
2. **Данные участника 1 лежат в `data/`** (`prs.json`, `all_prs.json`, `author_history.json`). Из корня проекта запусти:

```
python mock_scores.py
python p4.py --dir mock_out
```

`mock_scores.py` пишет случайные баллы в правильном формате в отдельную папку `mock_out/`, вместе с копиями данных: в `data/` лежат настоящие данные, и случайным баллам рядом с ними не место. Разметка откатов и уровни уже настоящие, их можно проверять. Связи риска с откатами на случайных баллах не будет, и отчёт так и скажет.

3. **Участник 2 прислал оценки.** Положи оба файла, `scores.json` и `run_stats.json`, в `data/` и запусти `python p4.py`. Брать нужно оба: по `run_stats.json` отчёт понимает, настоящая это модель или заглушка.
4. **Пришли `human_scores.csv` и `scores_style.json`.** Положи их в `data/` и запусти `python p4.py` ещё раз.

Бланк для ручной оценки участнику 5 делает команда `python validate.py --human-template 20`.

## Что проверить глазами

- **Откаты.** `outcomes.py` печатает список вида «#154: исправление в #177». Открой на GitHub пять таких пар и убедись, что второй PR действительно чинит первый. Это твой ответ жюри на вопрос «откуда вы знаете, что PR проблемный».
- **Покрытие истории.** Если `outcomes.py` пишет «список закрытых PR начинается с…», часть откатов не попала в данные: попроси участника 1 перезапустить выгрузку с большим `--all-pages`.
- **Окно наблюдения.** PR моложе 14 дней в расчёт не идут. Если таких большинство, участнику 1 нужно выгружать с `--min-age-days 30`.
- **Множители.** Если почти у всех 0,90 или 1,15, нормы в конфиге не подходят к шкале модели. Поставь в `config/levels.json` значение `"calibrate_norms": "always"`: норма уровня станет медианой по людям этого уровня.
- **Вывод отчёта.** В `validation.md` стоит один из трёх выводов: связь есть, связь не доказана, данных мало. Заголовок графика повторяет его. Не переписывай заголовок вручную в лучшую сторону.

## Как считается множитель

1. По каждому разработчику берётся медиана баллов по каждому критерию.
2. Сводный балл равен сумме медиан сложности, качества и ясности с весами уровня.
3. Множитель равен `1 + 0,5 × (балл − норма) / норма` и ограничен диапазоном от 0,9 до 1,15.
4. Если PR меньше трёх, множителя нет: в файле `null` и флаг `insufficient_data`.

Все числа настраиваются в `config/levels.json`: веса, нормы, границы множителя, границы уровней, пороги флагов. В поле `level_overrides` можно задать уровень человека вручную, например `{"octocat": "senior"}`.

## Ответы для жюри

- **Почему медиана, а не сумма?** Сумма растёт от числа PR, и её можно накрутить дроблением работы. Медиана от числа PR не растёт; поток мелких PR дополнительно получает флаг `many_small_prs`.
- **Почему риск не входит в множитель?** Рискованность изменения не заслуга и не вина автора. Риск нужен для проверки метода: его можно сравнить с независимым фактом, откатом.
- **Почему на графике интервалы?** Проблемных PR мало. «4 из 15» и «40 из 150» дают одинаковую долю, но верить им можно по-разному, и интервал это показывает.
- **Откуда уровни?** В открытом репозитории это допущение по числу прошлых PR автора. В компании уровни берутся из HR-системы.
- **Не угадывает ли модель просто по размеру PR?** В отчёте рядом стоят два числа AUC: для балла риска и для размера PR в строках. Если первое не выше второго, модель ничего не добавляет к размеру, и это надо сказать прямо.
